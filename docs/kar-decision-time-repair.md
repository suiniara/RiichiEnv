# KAR 离线决策时点修复与迁移说明

**审查和实现基线：** `f70684ef7aa69e56e6a530dcca13326fbf2c83b5`，分支 `kar/riichienv-v1-20261117`。开始时本地和 fork 同名分支相同；工作区原有六个文档变更未改动。本说明记录其后的实现差异，不覆写以该提交为基准的设计文档修订。未提交或推送。

## 根因与修复

旧 `replay_game()` 在解析已决定的 `dahai`、鸣牌或和牌时才取原生观察和 Ledger 快照。某些公开事件虽然列在结果事件之前，却是在用户选择提交之后才产生。按结果事件取样，导致输入包含了该选择本不应看到的事实。

- 自家摸牌，包括岭上摸牌，以及吃碰完成取得自家动作权后，冻结一个 `ReplayOpportunity`：观察、快照（含历史和 positions）及完整映射候选。立直宣言和对应舍牌用同一个冻结时点。随该动作提交而公开的宝牌继续入账，但不刷新已打开的机会。
- `dahai` 应用后立即冻结活跃响应者的机会。`reach_accepted` 更新真实公开账本；吃、碰、大明杠、荣和标签仍匹配该窗口已冻结的观察和合法动作，不重新取较晚的状态。多个荣和可共用这个已冻结的窗口。杠响应使用原生 preview；连续杠中，加杠在实际打开抢杠窗口前随声明提交一并公开的上一个杠指示牌仍可见，暗杠抢杠不提前看到后续提交宝牌。
- 不修改 `normalize_records()` 的公开事件顺序，也不删宝牌或接受立直事件。之后的观察、规则校验、支付与终局仍用按实际顺序演进的 Ledger。已知唯一下一摸牌的非平凡 Pass 仍可监督；私有 marker 到真正观察该摸牌时才写入。未成立的鸣牌意图及未知、被覆盖的选择不被猜作 Pass。
- 舍牌公开响应 mask 从冻结的舍牌快照计算；保持全局动作身份、完整候选、响应类别、模型规模、三项损失权重和训练集固定 rho。

代码位置：[冻结的选择上下文](../src/riichienv/kar/decision.py)、[机会打开与标签关联](../src/riichienv/kar/audit.py)、[输入审计标识](../src/riichienv/kar/input_audit.py)。`FullSyntheticDataset` 现在从 [`game_count_contract()` 与 `learning_contract()`](../tests/kar/production/test_full_trainer.py) 取得当前字段，不绕开生产 manifest、发布或恢复校验。

## 反例及对照

永久测试 [`test_decision_time_parity.py`](../tests/kar/test_decision_time_parity.py) 用完整 136 张合法物理牌墙，经真实 `KARAgent.choose`、原子提交及在线投影。再用同一局原生结果打包合成服务器记录并运行实际 `normalize_records → replay_game → on_decision`。用结果事件的来源标识关联同一动作，不手填相同 cutoff 或离线快照。比较完整 prefix 字节、记录字段、positions 和合法候选；也校验公开事件种类顺序不变。

| 反例 | 原实现（在线 / 离线） | 修复后 |
|---|---|---|
| 大明杠后舍牌 | cutoff 5 / 6，指示牌 1 / 2 | 取 cutoff 5、1 张指示牌；后续仍见新指示牌 |
| 加杠后舍牌 | cutoff 14 / 15，指示牌 1 / 2 | 取 cutoff 14、1 张指示牌；后续仍见新指示牌 |
| 立直宣言牌被吃、碰、大明杠 | cutoff 4 / 5，离线已扣 1000、增立直棒并标记接受 | 响应取 cutoff 4、25,000 点和未接受；后续接受时才见 24,000 点、1 棒 |

同墙碰与荣和的前缀一致、监督动作后缀不同；荣和不收立直棒。交换下一张指示牌所在死墙位置的两局中，当前未揭示时输入一致，后续确实不同。另覆盖普通摸打、暗杠、连续杠、连续加杠抢杠，以及立直牌的 Ron 和 Pass。旧实现实跑 6 失败、5 通过；扩展后的最终 13 个对拍全部通过。旧训练 fixture 实跑 2 失败、1 通过，失败在进入训练前的生产校验。

## 合同变更及重建边界

| 标识 | 本轮 |
|---|---|
| `input_pipeline_version` | `semantic_public_clock_frozen_decisions_v3`（旧 `semantic_public_clock_terminal_reveal_v2` 不兼容） |
| `training_config_version` | `explicit_train_split_scale_v5_decision_time`（原 V4 训练配置被拒绝） |
| Schema、公开语义时钟、规则 mask、模型 | 保持不变；artifact 容器仍为 V4，由输入子版本及源码身份区别 |

输入审计报告显式含当前子版本；数据、runtime、缓存及发布合同从 `artifact_contract()` 绑定输入版本；训练配方也包含它。样本已经泄漏本次动作结果时，不能只改旧 manifest/hash：应从可核验的原始记录重新运行标准化、重放审计/验收，再生成相应的派生 SQLite、索引、选集与指纹。旧证据、历史/KV 缓存和训练配方不能冒充新合同；旧 checkpoint/恢复、依赖旧输入的事件支持、校准、有限策略选择和发布需按对应依赖重建或重新验证，不能因网络形状一样宣布精确续训兼容。现有权重与真实数据均未修改或重建。
